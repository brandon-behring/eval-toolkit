## 1. Executive summary

The audit surveyed **27 public methods + 6 dataclasses + 1 Protocol** across
all 11 modules in eval-toolkit v0.2.0. Each math-kernel method received a
full literature review (canonical primary sources verified, ≥2 recent
2020+ papers surveyed, ≥1 library cross-check). Non-math modules received
a lighter "does this match current Python community pattern" pass.

### Industry-standard rating

The toolkit rates **B+** against sklearn / scipy / statsmodels as
benchmark peers for a methodology-first ML library. The two biggest
deltas to A-:

- **Reference-impl tests are sparse** — only `pr_auc` is value-equality-tested
  against its sklearn equivalent. For a "wraps and validates" library, one
  such test per wrapped function is the table-stakes contract.
- **Visual-regression tests on plotting are absent** — 12 plot helpers, 0
  pixel-comparison tests. `pytest-mpl` is the community-standard fix.

The home-designed-Python discipline (no Pydantic, no LangChain, no Hydra,
no custom exception hierarchy) holds up well against the no-go list, and
the engineering choices (Paul Tol palette, pure/IO split in harness,
anchor-based markdown rendering, frozen dataclass results, Protocol-based
strategy seam) are best-in-class for the methodology-PoC scope.

### Top-5 P1 (correctness) gaps

1. **`expected_calibration_error` lacks `y_score ∈ [0, 1]` validation**
   (`metrics.py:457–527`). Any uncalibrated logit silently produces a
   meaningless ECE. Hypothesis suite at `test_metrics_props.py:84–95` does
   not catch this because Hypothesis only generates `[0, 1]` floats.
   Same gap in `expected_calibration_error_equal_mass`. **Fix**: ~5 LOC in
   `_validate_inputs` or per-function check.

2. **`fit_platt_calibrator` is NOT canonical Platt** (`calibration.py:400–446`,
   source-verified vs `sklearn.calibration._SigmoidCalibration`). sklearn
   implements Platt 1999 §2.2 + Lin et al. 2007 with Laplace-smoothed
   targets `T[y>0] = (n_pos+1)/(n_pos+2)` and unregularized binomial NLL.
   Our wrapper uses `LogisticRegression(solver="lbfgs")` with default L2.
   Two distinct regularization mechanisms diverge under class imbalance /
   near-separable data (~1–3% ECE gap at n≥200). **Fix**: docstring update
   acknowledging the deviation, OR copy ~30 LOC of `_sigmoid_calibration`
   from sklearn into our module.

3. **`bayes_optimal_threshold` attribution misleading** (`calibration.py:189`).
   Our formula `t* = c_fp(1-π) / (c_fp(1-π) + c_fn·π)` is the *prior-corrected*
   form; Elkan 2001 §4's posterior-formula is the prior-independent
   `t* = c_fp / (c_fp + c_fn)`. The two agree only under symmetric costs.
   Our formula is correct for our intended use; docstring needs a
   qualifying paragraph. **Fix**: ~10 LOC docstring update.

4. **Bootstrap module lacks kwarg-only break after positional args**
   (`bootstrap.py`). `bootstrap_ci(y, s, metric, n_resamples=1000, ...)`
   allows positional misuse of every keyword. sklearn made this exact
   change in 0.23 (2020) for the same reason; our `plotting.py` is
   correctly kwarg-broken. **Fix**: insert `*,` separator in 5 signatures;
   breaking change but acceptable pre-1.0.

5. **Reference-impl tests are sparse**. The toolkit explicitly "wraps
   sklearn references with input validation" yet has no
   `bootstrap_ci ≡ scipy.stats.bootstrap`, no `roc_auc ≡ sklearn`, no
   `reliability_curve ≡ sklearn.calibration.calibration_curve` test. Only
   `pr_auc` is sklearn-equality-tested. **Fix**: 5–7 small tests across
   modules.

### Top-5 nice-to-haves (P2 / new methods)

- **Brier score + Murphy 1973 decomposition** in `metrics.py` (~30 LOC).
  Strictly proper; decomposes into reliability/resolution/uncertainty;
  captures what ECE misses; recommended by Vaicenavicius 2019, Wang 2023+,
  Roelofs 2022.
- **`expected_cost(predictions, labels, matrix)` method on `CostMatrix`**
  (~15 LOC). Closes the loop between threshold choice and cost evaluation;
  natural composition with `bayes_optimal_threshold`.
- **NaN/Inf rejection in `_validate_inputs`** (`metrics.py`, ~2 LOC).
  Harmonizes 7 methods at once with `score_distribution_summary` (which
  already validates) and prevents silent ranking distortions.
- **Visual regression via `pytest-mpl`** for `plotting.py` (12 helpers, 0
  pixel-comparison tests today). One decorator per smoke test + baseline
  image fixtures.
- **Hypothesis strategy consolidation** into `tests/strategies.py`.
  `_balanced_binary_array` and `_score_array` appear verbatim across 3
  property test files; Hypothesis docs explicitly recommend a shared
  strategies module.

### Estimated v0.3.0 ladder (P1 + selected P2)

If we ship all 5 P1 fixes plus the 5 nice-to-haves above, the v0.3.0
implementation is approximately:

- **~200 LOC** of new/changed source code (mostly small additions:
  validation, Brier, expected_cost; one larger Platt rewrite if chosen)
- **~150 LOC** of new tests (reference-impl tests, sklearn equivalence,
  Hypothesis strategy consolidation)
- **~80 LOC** of docstring fixes (Platt/Bayes/oracle T attribution +
  See Also cross-references)
- **5–6 commits** on the per-category ladder pattern used in v0.1.0/v0.2.0

### v0.4.0+ backlog (deferred — out of v0.3.0 scope)

- Bias-corrected ECE (Roelofs 2022 / Kumar 2019) as opt-in
  `estimator="debiased"` kwarg
- Beta calibration (Kull et al. 2017) — empirically dominates Platt
- Histogram binning calibrator (Gupta et al. 2020 distribution-free guarantees)
- MinHashLSHStrategy (no measurable user signal yet; ~300–500 LOC)
- Studentized bootstrap-t (Algeshiemer 2024) — best CI coverage but
  per-resample SE doubles compute
- CV-CLT (Bayle et al. 2020) — better-in-class for cross-validation,
  irrelevant until CV is added to the toolkit
- `tests/strategies.py` Hypothesis refactor (counted in v0.3.0 above; can
  defer if scope is tight)

## 2. Methodology

### Audit dimensions per method (math kernels)

For each public method, the audit collected:

1. **Algorithmic correctness**: implementation vs cited primary source
2. **Citation quality**: do existing References resolve? Primary or derivative?
3. **Library cross-check**: comparison vs sklearn / scipy / netcal / MAPIE /
   statsmodels / datasketch
4. **Edge case coverage**: canonical warnings vs current handling
5. **Recent literature (2020+)**: superseding methods? bias corrections?
6. **Test coverage**: unit + property + doctest

### Audit dimensions per module (non-math)

Lighter — verify patterns rather than algorithms:

1. **Pattern fitness** vs current Python community standard (sklearn
   estimator API, matplotlib gallery, pathlib + dataclasses + Protocol,
   PyTorch Lightning seed_everything, etc.)
2. **Stdlib alignment** (`pathlib` over `os.path`; `dataclasses` over
   manual `__init__`; `typing.Protocol` over abstract base classes)
3. **Best-practice gaps** (PEP 563/604 syntax, `from __future__ import
   annotations`, type completeness, deprecation handling)

### Sources surveyed

Canonical references (already cited; verified to exist + match
implementation):

- Davis & Goadrich 2006, Saito & Rehmsmeier 2015, Hanley & McNeil 1982
- DeGroot & Fienberg 1983, Naeini et al. 2015, Nixon et al. 2019
- Elkan 2001, Platt 1999, Niculescu-Mizil & Caruana 2005, Zadrozny &
  Elkan 2002

  Davison & Hinkley 1997; Cohen 1988

Library cross-checks performed:

  `sklearn.neighbors` — direct source inspection (where claimed in this
  doc; spot-checked elsewhere)

### Stance preserved

Recommendations bias toward **home-grown improvements** over swapping in
heavy dependencies. The toolkit no-go list (no Pydantic, no LangChain, no
config frameworks, no custom exception hierarchies, no `Result[T, Error]`
patterns) is preserved. Where a third-party library is the right answer,
the recommendation is to **document the integration recipe** rather than
ship the dependency.

### docs.py

## 5. Cross-cutting findings

### 5.1 Testing methodology (B+ → A- with these fixes)

**Strong**:
- 90% coverage gate enforced via `branch=true`
- 4-marker discipline: `unit` / `property` / `smoke` / `golden`
- 40 `@given` decorators across 6 files testing bounds, identities,
  idempotence, monotonicity, determinism, optimality, schema invariants
- Doctests on every math kernel run in CI
- Correct golden-test scope (only `docs.py` where output IS the contract)

**Weak**:
- **Only `pr_auc`** is value-equality-tested against sklearn
  (the rest are invariant-only). For a "wraps and validates" library, one
  reference-impl test per wrapped function is the table-stakes contract
  that sklearn / scipy / statsmodels would not ship without.
- **No visual-regression tests** — 12 plot helpers, 0 pixel comparisons.
  `pytest-mpl` is the community-standard fix.
- **Hypothesis strategies duplicated** across 3 files (`_balanced_binary_array`,
  `_score_array`). Consolidate into `tests/strategies.py` per Hypothesis
  docs recommendation.
- **`test_coverage_gap.py` is a 19KB grab-bag** — could be inlined into
  the relevant module test files.
- **No multi-Python CI matrix** (3.11 only). `tox` / `nox` would close
  this gap.

### 5.2 Documentation completeness

- **NumPy docstring sections**: most public methods have Parameters /
  Returns / Raises / Examples / Notes. References blocks are present on
  ~70% of math-kernel methods after v0.1.0 audit; remaining 30% should
  be filled.
- **Doctests**: 9 in v0.2.0 (all on math kernels). Non-math modules could
  add ~3–5 more doctests for `paths.resolve_repo_path`,
  `provenance.file_sha256`, `seeds.set_global_seeds`, `docs.render_text`.
- **`See Also` cross-references absent** across the 89-symbol public API.
  `pr_auc` should reference `roc_auc`, `headline_metrics`,
  `sklearn.metrics.average_precision_score`. Single most-impactful
  documentation polish for v0.3.0.
- **Math notation**: Unicode (`π`, `T`) with English-comment alias on
  first appearance is mostly consistent (one case fixed in v0.1.0:
  `bayes_optimal_threshold`).

### 5.3 Public API consistency

- **Kwarg conventions**: `plotting.py` is correctly kwarg-broken via `*,`
  separator; `bootstrap.py` and `harness.evaluate_scorer_on_slice` are
  not. Highest-leverage v0.3.0 API hardening.
- **`BootstrapCI.to_dict()` field-name aliasing**: field is
  `point_estimate`; dict key is `"mean"`. Trips users reading the
  dataclass before the JSON. Pick one and unify.
- **Exception types**: ValueError / TypeError / RuntimeError /
  FileNotFoundError / KeyError. No custom hierarchy. Audit confirms
  consistency.
- **Naming**: snake_case fns, PascalCase classes, UPPER_SNAKE constants.
  Audit confirms consistency.
